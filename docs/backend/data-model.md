# Предварительная модель данных

> **Простыми словами.** Какие данные система хранит и передаёт: документы, фрагменты, версии базы знаний, вопросы и ответы, примеры для оценки качества. Отдельной базы данных нет — всё хранится в файлах.

Статус: DRAFT, SRC-003; файловое хранение без БД — CONFIRMED, SRC-002, ADR-001. Ниже логическая схема, не требование конкретного формата сериализации.

## Корпус и снимок

| Сущность | Обязательные данные | Ограничения |
|---|---|---|
| KnowledgeBase | mode (`ask` или `sell`), отображаемое название, выбранный при запуске index_version | Одна база на режим (ADR-004, предварительно). Базы собираются и публикуются независимо |
| Document | document_id, source_hash, title, format, extracted_text_hash | document_id связан с байтами исходника; имя/путь не служит единственным ID |
| Document metadata | locator/разделы, extraction_version; при наличии дата/владелец/статус актуальности | Неизвестные значения null; метаданные не выдумывать |
| Chunk | chunk_id, document_id, ordinal, text, locator, search_tokens | ordinal детерминирован внутри документа; text отображаемый, search_tokens нормализованы |
| IndexManifest | index_version, mode базы, schema_version, pipeline_config, config_hash, документы/фрагменты, версии извлекателя и BM25, порядок входов | Однозначно описывает снимок, не содержит секретов |
| BuildReport | попытка сборки, принятые/отклонённые входы, причины, counts, результат проверки | Сборка с ошибками не объявляется готовой |

Числа страниц, разделы и строки хранятся только если извлечение позволяет восстановить их. Базовый locator содержит section/page/start_line/end_line с null для неизвестного. Для TXT/MD строки соответствуют сохранённому извлечённому тексту; страницу не придумывать. Если длинный абзац разделён, ordinal и текст различают фрагменты с одинаковым диапазоном строк.

Каноническое представление manifest исключает нестабильные поля вроде времени сборки из вычисления index_version. Время и идентификатор попытки остаются в BuildReport. Идентичность не обещает побайтовой одинаковости любого файла библиотечного индекса; обязательны одинаковые логические фрагменты и результаты retrieval в фиксированном окружении.

## Данные запроса

| Сущность | Поля | Жизненный цикл |
|---|---|---|
| Query | request_id, question, mode, index_version базы режима, deadline | В памяти на время обработки; без истории |
| SearchHit | chunk_id, score, rank | В памяти; rank после стабильной сортировки |
| Context | упорядоченные полные фрагменты, локальные citation_id, token_budget | В памяти запроса; подмножество SearchHit |
| GenerationResult | outcome, reason, message, cited_chunk_ids | Внутренний проверяемый результат, не прямой ответ провайдера |
| ChatResult | request_id, mode, index_version, outcome, reason, message, sources | Схема API; история только в памяти вкладки |
| SourceView | chunk_id, document_id, title, locator, text, index_version, mode | Чтение неизменяемого снимка |

citation_id вида S1 локален конкретному ответу, chunk_id стабилен внутри версии pipeline. Backend строит sources из Context и cited_chunk_ids. Сырые provider ID не заменяют request_id; сырой prompt не сохраняется автоматически.

## Оценочные данные

EvaluationCase: case_id, question, mode, category, answerability, index_version, relevant_chunk_ids, ожидаемые ключевые факты/уточнения/конфликты, источник разметки, разметчик, split. Оценочный набор — отдельный разрешённый исследовательский артефакт, не копия пользовательских логов.

EvaluationRun: run_id, corpus/index/config/dataset/prompt/model versions, окружение, выбранные параметры генерации, seed если поддерживается, время запуска, число повторов, метрики по примерам и агрегаты. Отдельно фиксировать ошибки/пропуски и знаменатели. Ответы для экспертной оценки можно сохранять только по согласованному режиму OPEN-003, OPEN-005.

## Хранение и обновление

PROPOSED, SRC-003: у каждой базы знаний свой набор снимков; неизменяемая папка на снимок с manifest, извлечённым текстом, фрагментами, индексом; отдельные отчёты сборки/экспериментов. Конкретные файлы — планируемые, перечислены в project-map.md. Активация после полной сборки и перезапуска Backend; миграции БД не нужны.

Разные байты исходника — новая версия document_id; смена chunking/нормализации — новые chunk_id/index_version и перепроверка разметки. Полностью одинаковые байты предлагается дедуплицировать с сохранением списка входных имён в отчёте; смысловые дубликаты не удалять автоматически. Политика актуальности OPEN-004 может изменить состав корпуса, но не переписывает уже использованный снимок.
