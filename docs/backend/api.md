# Предварительные API-контракты

Все точные поля, пути, HTTP-коды и правила этого файла — DRAFT, SRC-003. Направление «ответ целиком» согласовано SRC-002. Язык программирования и способ описания схем OPEN-007 ещё не выбраны. JSON-примеры — спецификация, не код приложения.

## Общие положения

JSON UTF-8; штатный результат HTTP 200. Вход question — строка, крайние пробелы удаляются, Unicode-кодовые точки считаются после trim. Неизвестные поля тела отвергаются 400/INVALID_REQUEST, чтобы history не подключалась незаметно. Backend проверяет вход независимо от UI. Секретов и сырых исключений в ответах нет.

request_id генерирует Backend для каждого обращения и возвращает в успешном/ошибочном envelope, насколько обработчик смог сформировать ответ. При сетевом разрыве UI может его не узнать. ID не является ключом устранения повторов. Клиент связывает сетевую операцию с сообщением локально.

MAX_QUESTION_CHARS, MAX_ANSWER_CHARS и лимиты времени — OPEN-008. HTTP body limit и формат его безопасной ошибки должны быть согласованы с выбранным сервером до реализации; чрезмерное тело → 413/PAYLOAD_TOO_LARGE. Другой content type → 415/UNSUPPORTED_MEDIA_TYPE. Неизвестный путь → 404/NOT_FOUND, неверный метод → 405/METHOD_NOT_ALLOWED.

## API-CHAT-001

`POST /api/chat/query`

Связи: REQ-001…006; BEH-CHAT-001…009/011…014; ARCH-BACKEND-001/002, ARCH-RAG-002/003/004.

Вход:

```json
{"question": "Какие документы нужны для указанного внутреннего процесса?"}
```

История, настройки модели, top_k и пути корпуса не принимаются от клиента. Они задаются согласованной серверной конфигурацией.

Успешный результат (пример только структуры; данные синтетические):

```json
{
  "request_id": "request-demo",
  "index_version": "index-demo",
  "outcome": "answer",
  "reason": null,
  "message": "Для учебного процесса нужны формы A и B [S1].",
  "sources": [
    {
      "citation_id": "S1",
      "chunk_id": "chunk-demo",
      "document_id": "document-demo",
      "title": "Синтетическая инструкция",
      "locator": {"section": null, "page": null, "start_line": 1, "end_line": 3},
      "excerpt": "Для учебного процесса используются формы A и B."
    }
  ]
}
```

Все поля envelope обязательны. request_id/index_version/message — непустые строки, sources — массив, reason — null либо значение из таблицы. Локатор — объект со всеми четырьмя полями; неизвестные значения null, строки/страницы начинаются с 1. excerpt формирует Backend из действительного фрагмента, а не принимает цитату модели на веру. Предел excerpt = EXCERPT_MAX_CHARS, значение OPEN-008; обрезка не меняет полный фрагмент.

| outcome | reason | Условие |
|---|---|---|
| answer | null | Подтверждённый контекстом ответ, хотя бы один источник |
| partial | incomplete_context | Подтверждённая часть плюс явный пробел, хотя бы один источник |
| insufficient | no_candidates или insufficient_context | Нет пригодных кандидатов либо их содержания недостаточно; no_candidates всегда sources=[] |
| clarification | ambiguous_question | Нужно назвать объект/условия; источники могут отсутствовать |
| conflict | conflicting_context | Обнаружены несовместимые сведения, хотя бы один источник; конфликт может быть внутри одного фрагмента |

message — безопасный текст до MAX_ANSWER_CHARS. Маркеры [S1], [S2]… соответствуют sources. Все возвращённые источники упомянуты в message, все маркеры разрешаются; дубликатов citation_id/chunk_id нет. Для недостаточности/уточнения sources может быть пустым. Сервер возвращает только использованные источники, а не весь top_k. index_version соответствует снимку данного запроса, даже при sources=[].

Ответ без кандидатов формирует Backend. Остальные исходы выбирает генератор по prompt, Backend проверяет структуру и ссылки. Это не автоматическая проверка правильности текста. Детальный внутренний контракт — [generation.md](../rag/generation.md).

### Ошибки API-CHAT-001

```json
{
  "request_id": "request-demo",
  "error": {
    "code": "LLM_UNAVAILABLE",
    "message": "Сервис ответа временно недоступен. Можно повторить вопрос."
  }
}
```

| HTTP | code | Значение / действие UI |
|---|---|---|
| 400 | INVALID_REQUEST | JSON/схема неверны; исправить вход |
| 400 | INVALID_QUESTION | Пустая строка; ввести вопрос |
| 400 | QUESTION_TOO_LONG | Превышен предел; сократить вопрос |
| 413 | PAYLOAD_TOO_LARGE | Тело больше разрешённого; сократить запрос |
| 415 | UNSUPPORTED_MEDIA_TYPE | Ожидается JSON |
| 503 | INDEX_NOT_READY | Нет готового выбранного снимка |
| 503 | RETRIEVAL_UNAVAILABLE | Ошибка поиска, не отсутствие сведений |
| 503 | LLM_UNAVAILABLE | Недоступен провайдер/модель |
| 504 | REQUEST_TIMEOUT | Истёк бюджет обработки или ожидания LLM |
| 502 | INVALID_LLM_RESPONSE | Схема/исход/ссылки результата невалидны |
| 500 | INTERNAL_ERROR | Непредвиденная ошибка без раскрытия деталей |

Retry после технической ошибки только по действию пользователя; нового результата успешность не гарантируется. Поля внутренней ошибки провайдера не проксируются. Некорректная серверная конфигурация выявляется при запуске, а не сообщается как недостаток знаний.

## API-SOURCE-001

`GET /api/indexes/{index_version}/sources/{chunk_id}`

Связи: REQ-004/006; BEH-CHAT-010/015; UI-CHAT-004; ARCH-BACKEND-003.

Параметры — непрозрачные идентификаторы, не пути. Lookup только в manifest указанной версии; запрещено использовать параметр для произвольного чтения файлов.

200 возвращает request_id, index_version и source с полями chunk_id, document_id, title, locator, text. text — полный сохранённый текст фрагмента. citation_id не нужен: он локален ответу чата. source не включает абсолютный путь или оригинальный бинарный файл.

Ошибки: 400/INVALID_REQUEST при неверных параметрах; 410/INDEX_VERSION_UNAVAILABLE при отсутствии снимка; 404/SOURCE_NOT_FOUND при отсутствии фрагмента в существующем снимке; 500/INTERNAL_ERROR при внутреннем сбое. Envelope ошибок общий. Источник из другой версии не подставляется. Предложено хранить используемые снимки на время пилота; точный срок и доступ — OPEN-005. Если снимок удалён, включённый ранее excerpt остаётся в сообщении текущей вкладки.

## Проверки контракта

TEST-API-001 проверяет типы, обязательность и неизвестные поля, пределы, enum и соответствие outcome/reason/sources, схемы обоих ответов и ошибки. TEST-CHAT-010/015 проверяют версии источников. Реальные корпоративные знания не нужны для проверки API; используются синтетические фикстуры. До реализации требуется согласовать этот DRAFT и численные параметры.
