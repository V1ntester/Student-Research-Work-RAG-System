# Архитектура Backend

Направление модульного монолита CONFIRMED, SRC-002/ADR-001. Компоненты и точные внутренние контракты ниже DRAFT, SRC-003. Реализация отсутствует.

## Компоненты

| ID | Ответственность | Не отвечает за |
|---|---|---|
| ARCH-BACKEND-001 | HTTP-адаптер: валидация, request_id, сериализация [API](api.md), безопасные ошибки | Алгоритм BM25 и предметные решения |
| ARCH-BACKEND-002 | Оркестратор Query: один снимок, deadline, retrieval → context → generation → validation | Разбор файлов, сетевой интерфейс провайдера |
| ARCH-BACKEND-003 | Доступ к снимкам и фрагментам через manifest | Чтение произвольных клиентских путей |
| ARCH-BACKEND-004 | Конфигурация, безопасные технические события, проверка готовности при запуске | Хранение секретов в индексах/Frontend |

Все определения ARCH-BACKEND: DRAFT, SRC-003. [RAG-компоненты](../rag/architecture.md) являются внутренними модулями Backend, а не дополнительными микросервисами. Оценка может вызывать их напрямую и через API для разных видов проверки.

## Обработка запроса

1. Адаптер проверяет JSON/question, создаёт ID и deadline.
2. Оркестратор получает готовый неизменяемый снимок.
3. ARCH-RAG-002 возвращает упорядоченные кандидаты.
4. ARCH-RAG-003 отбирает целые фрагменты под бюджет prompt.
5. Если контекст пуст, Backend возвращает insufficient/no_candidates без LLM.
6. Иначе ARCH-RAG-004 вызывает модель через изолированный provider-adapter.
7. Проверяется схема/исход/ссылки; sources собираются из снимка, результат передаётся HTTP-адаптеру.
8. В логе только ID, версия, этап, длительность, количество фрагментов и код исхода/ошибки без сырых данных.

Frontend не имеет прямого доступа к LLM и индексным файлам. Техническое исключение переводится в код API, не в ответ «ничего не найдено».

## Внутренние границы

- `retrieve(question, snapshot, config)` → SearchHit[] либо RetrievalError.
- `select_context(hits, snapshot, prompt_budget)` → Context либо ConfigError.
- `generate(question, context, generation_config, deadline)` → GenerationResult либо ProviderError/Timeout/InvalidResult.
- `read_source(index_version, chunk_id)` → SourceView либо UnknownVersion/UnknownChunk.

Это описания контрактов, не обязательные имена функций. Типы определены в [data-model.md](data-model.md). Ни один компонент не импортирует состояние UI.

## Таймауты, повтор и готовность

Значения OPEN-008. Предлагаемые отношения: 0 < UI_WAIT_HINT_MS < REQUEST_TIMEOUT_MS < CLIENT_TIMEOUT_MS; LLM_TIMEOUT_MS <= REQUEST_TIMEOUT_MS, при этом провайдер получает оставшийся бюджет общего deadline. Таймаут Backend покрывает retrieval и generation целиком, включая overhead. Реализуемый способ остановки/изоляции долгой операции зависит от OPEN-007 и должен быть проверен TEST-CHAT-007. Потеря клиента не доказывает отмену работы.

Автоматических повторов LLM/HTTP нет, provider SDK не должен добавлять их незаметно. Одна операция UI не означает серверного запрета параллельных вкладок. Нагрузочные лимиты определяются для пилота через OPEN-005/008; очереди/брокеры не добавляются.

При запуске проверить конфигурацию, доступность выбранных файлов, целостность manifest и совместимость версии индекса. Невалидная конфигурация — явная ошибка запуска. Отсутствие готового снимка при работающем API — INDEX_NOT_READY. Онлайн-проверка провайдера не должна передавать реальные данные до разрешения.

## Конфигурация и запуск

Нужны путь к разрешённому снимку, pipeline/model/prompt versions, лимиты и настройки провайдера. Секрет — отдельная серверная переменная/локальный непубликуемый файл. Будущий пример конфигурации содержит только имена и безопасные заглушки; подготовка инструкции запуска входит в REQ-013 после выбора стека.

Документы и индексы не публиковать как статическую директорию Frontend. Разрешённые источники выдаются через точный lookup. CORS/адреса прослушивания выбираются по среде OPEN-005; публичный доступ не подразумевается отсутствием регистрации.
