## Статусы

| Статус | Значение |
|---|---|
| CONFIRMED | Человек явно подтвердил содержание; разрешение реализации не подразумевается |
| DRAFT | Детализированный черновик, ожидающий проверки |
| PROPOSED | Новое предложение AI-агента |
| NEEDS_DOMAIN_REVIEW | Предметное допущение требует проверки экспертом |
| APPROVED | Конкретное требование/решение согласовано и разрешено к реализации |
| DEPRECATED | Отменено или заменено; ID сохраняется |

Статусы не образуют автоматическую линейную последовательность. Возможен возврат на уточнение. Устаревшая запись ссылается на замену. Изменение согласованного содержания требует нового подтверждения; прежнее согласование не наследуется молча.

## Минимальный формат записи

Для требования: `ID; содержание; статус; источник; критерий проверки/сценарий; открытые зависимости`. Источник должен объяснять происхождение, а не просто указывать на соседний документ. У блока однотипных сценариев/тестов допустима общая явная область статуса и источника.

ID: GOAL — цель, REQ — требование (включая нефункциональные), RULE — инвариант, BEH — сценарий, UI — интерфейс, API — контракт, ARCH — компонент/граница, TEST — план проверки, ADR — решение. SRC — источник, OPEN — открытый вопрос, HYP — исследовательская гипотеза. Диапазон вида BEH-CHAT-001…015 — краткая запись существующих ID от BEH-CHAT-001 до BEH-CHAT-015 включительно; это не отдельный ID.

Определения ID имеют одного владельца. Повторное упоминание является ссылкой, а не новой записью. [Карта](project-map.md) хранит трассируемость, [решения](decisions/README.md) — открытые вопросы. Файлы реализации и тестов появятся только после разрешения; сейчас их пути не используются как ссылки.

## Критерий готовности к реализации

Для выбранного вертикального среза: известны входы/выходы и ограничения, проверяемы сценарии, согласованы зависимости и правила, устранены блокирующие OPEN, есть план тестов и явный APPROVED от человека. Пока этот критерий не выполнен. Открытые вопросы не препятствуют завершению текущей документации.
