## Ввод и взаимодействие

PROPOSED, SRC-003: Enter отправляет, Shift+Enter добавляет строку; во время композиции ввода Enter не отправляет. Кнопка всегда остаётся альтернативным способом. При processing отправка отключена, но черновик следующего вопроса можно редактировать; повторное действие не теряет черновик. При локальной ошибке валидации поле сохраняет введённое значение. При принятой отправке очищается, вопрос остаётся в списке.

PROPOSED, SRC-003: режим фиксируется в момент отправки вопроса. Переключать режим можно и во время processing; это влияет только на следующий вопрос. Повтор ошибочного вопроса использует режим исходного вопроса. Как показывать режим у каждого сообщения, макет не определяет.

Кнопка повтора создаёт новый запрос исходного вопроса с новой локальной операцией; прежний исход не стирается. Повтор доступен после error/result_unknown, не запускается автоматически. Перезагрузка очищает историю и черновик; предупреждение о перезагрузке/восстановление истории не входит в MVP.

## Состояния UI и контракт

| Состояние | Представление | Доступные действия |
|---|---|---|
| ready | Пустой чат/предыдущие сообщения, поле вопроса | Ввести, отправить, открыть прежний источник |
| processing | Текст ожидания; после UI_WAIT_HINT_MS дополнительная подсказка | Читать, редактировать следующий черновик, открыть источник |
| answer | Полный ответ и источники | Новый самостоятельный вопрос, источник |
| partial | Подтверждённая часть и указание пробела | Новый полный вопрос, источник |
| insufficient | Причина недостаточности и безопасная подсказка | Уточнить формулировку новым вопросом |
| clarification | Просьба уточнить предмет/условие | Отправить новый вопрос с уточнением |
| conflict | Указание несовместимых сведений и основания | Прочитать источники, уточнить у владельца знаний |
| error | Понятная ошибка и сохранённый вопрос | Явно повторить или задать новый |
| result_unknown | Сообщение о неполученном результате и возможной обработке | Явно повторить или задать новый |

answer/partial/insufficient/clarification/conflict — исходы [API-CHAT-001](backend/api.md#api-chat-001). error — HTTP-ошибка. result_unknown — локальный сетевой исход; Backend его не возвращает.

## Источники и безопасность

Отображать server-generated excerpt из результата сразу; полный фрагмент получать через [API-SOURCE-001](backend/api.md#api-source-001). Включать index_version в запрос. Недоступность панели не удаляет ответ и не меняет его тип. Локатор может содержать раздел или строки; страницу не придумывать, если извлечение её не сохраняет.

RULE-UI-001: весь контент как текст. Ссылки S1… связываются только с объектами sources; произвольные markdown/HTML-ссылки модели не становятся навигацией. Источники не открывают локальные пути файловой системы.

REQ-016 (PROPOSED): метки поля/кнопок, клавиатурный фокус, читаемая индикация состояния, обозначение исхода словами, а не только цветом. После завершения обработки фокус пользователя не перехватывается; смена состояния доступна вспомогательным средствам.

### Вёрстка-заглушка Web/

Состояние на 2026-10-19. Основания: SRC-006 — вёрстка по макету на заглушках; SRC-009 — имитация чата с исходами по кодовым словам для дистанционной проверки контрольной точки. Это демонстрация интерфейса, не реализация. Она не является APPROVED для UI-CHAT-001…005, API или сценариев BEH.

- [Web/index.html](../Web/index.html), [Web/styles.css](../Web/styles.css), [Web/script.js](../Web/script.js): статическая страница без сборки и зависимостей. Сетка соответствует фреймам «Desktop - 1/2» и «iPhone … - 4/6».
- Ответы формирует заглушка в script.js в формате API-CHAT-001: `{question, mode}` → `{request_id, mode, index_version, outcome, reason, message, sources}`, ошибки — в формате envelope ошибок. Для подключения Backend её заменяет вызов `POST /api/chat/query`. Запросов в сеть нет, сведения в ответах вымышлены.
- Исход выбирается кодовыми словами в вопросе: «частично» → partial, «нет данных» → insufficient, «уточнить» → clarification, «противоречие» → conflict, «долго» → подсказка долгого ожидания и answer, «ошибка» → error (503/LLM_UNAVAILABLE), «нет связи» → result_unknown; иначе answer. Список показан проверяющему в чате «Как проверить демо» (M-15).
- Имитируется UI-часть сценариев: BEH-CHAT-001 (без источников), BEH-CHAT-002, BEH-CHAT-004, BEH-CHAT-005, BEH-CHAT-006/007 (отображение ошибки и повтор), BEH-CHAT-008, BEH-CHAT-009, BEH-CHAT-011, BEH-CHAT-012, BEH-CHAT-013, BEH-CHAT-014 (только подсказка ожидания), BEH-CHAT-016. Повтор после ошибки имитирует восстановление сервиса и даёт answer.
- Чаты боковой панели — временные, в памяти вкладки: «Новый чат» / «+» создаёт пустой чат, перезагрузка очищает все. Это не решение OPEN-012.
- Задержки демо (1,2 с ответ; 2,5 с подсказка ожидания; 5 с долгий ответ) — не значения OPEN-008. Лимит длины вопроса не проверяется: MAX_QUESTION_CHARS не выбран.
- Не реализованы: источники и панель источника (M-06 отложен; в демо sources = [], хотя для answer контракт требует источник), селекторы (OPEN-011), многострочный ввод (M-01).
- Запуск: открыть каталог Web/ любым статическим сервером, например `npx http-server Web -p 5173`.
