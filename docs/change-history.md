# История значимых изменений

> **Простыми словами.** Журнал значимых изменений проекта: что поменялось, когда и на каком основании.

Здесь фиксируются реальные согласования и появление базовой документации. Незавершённые предложения находятся в Update/ и реестре OPEN. Новые черновики не считаются принятыми техническими решениями.

## 2026-10-11 — Базовый комплект спецификаций

- Основание: SRC-001 — исходное задание; SRC-002 — пользователь сообщил, что предложенное решение устраивает, разрешил создание документов и оставил вопросы открытыми.
- Согласована область: исследовательский MVP, структура документации, BM25, модульный Backend, самостоятельные вопросы/полный ответ, источники, offline-подготовка корпуса и оценка.
- Создан предварительный комплект docs/, инструкции агентам, Service/ и Update/. Требования исходной концепции имеют CONFIRMED; новые алгоритмические/контрактные детали — DRAFT/PROPOSED; предметные допущения — NEEDS_DOMAIN_REVIEW.
- Добавлены сценарии, запланированные TEST, API и трассируемость. Кода и реализованных тестов нет. Новых результатов исследования или материалов эксперта нет.
- Открытые решения OPEN-001…009 сохранены без выдуманных ответов. Реализация не разрешена; APPROVED не присваивался.
- При проверке Git обнаружен локальный коммит 4fc49ea «docs v0.1» с частью базового комплекта; он не создавался агентом этой задачи. Оставшиеся документы и уточнения находятся в рабочем дереве. Отправка в remote этой задачей не выполнялась и состояние remote не проверялось.

## 2026-10-19 — Макет интерфейса и вёрстка-заглушка

- Основание: SRC-005 — макет коллеги в Figma и его первая вёрстка в Web/; SRC-006 — пользователь поручил довести вёрстку до соответствия макету на заглушках, без ввода и ответов.
- Было: макета нет, интерфейс описан только текстом. Стало: макет сопоставлен со спецификацией (interface.md, M-01…M-14), Web/ соответствует фреймам «Desktop - 1/2» и «iPhone … - 4/6».
- Новые элементы макета (режим «Продавать», селекторы параметров, список чатов) не согласованы и вынесены в OPEN-010…012. Требования, сценарии, API и статусы UI-ID не менялись; APPROVED не присваивался.
- Последствия: перед реализацией логики интерфейса нужны ответы на OPEN-010…012 и дополнение макета состояниями M-05…M-07.
- Уточнение того же дня (SRC-007): автор макета выбрал финальный мобильный стартовый экран «iPhone … - 4», варианты «- 1» и «- 2» исключены (M-11). OPEN-010 частично отвечен: режимы «Спросить» и «Продавать» используют две разные базы; изменение спецификации предложено, но не согласовано. Источники и панель источника (M-06) отложены пользователем.

## 2026-10-19 — Две базы знаний (предварительно)

- Основание: SRC-007 — автор макета: режимы «Спросить» и «Продавать» используют разные базы; SRC-008 — пользователь: «Предварительно вносим изменение для двух баз знаний».
- Было: один корпус и один снимок индекса; режима в запросе нет. Стало: у каждого режима своя база знаний и свои снимки; запрос содержит обязательный mode; поиск только в базе режима, без перехода в другую.
- Добавлены ADR-004, REQ-018, RULE-RAG-004, BEH-CHAT-016, UI-CHAT-005, TEST-CHAT-016. Изменены RULE-RAG-002, BEH-INDEX-001, TEST-INDEX-001, API-CHAT-001 (mode, INVALID_MODE), API-SOURCE-001 (mode в ответе), data-model, архитектура Backend и RAG, indexing, evaluation, план исследования, карта трассируемости.
- Статус: направление CONFIRMED предварительно; детали DRAFT/PROPOSED; APPROVED нет. Состав баз и прочие различия режимов не определены (OPEN-010).
- Цвет надписи «BRAND» оставлен #1E293B (SRC-008); вероятно, позже её заменит логотип.

Стало: заглушка API в формате API-CHAT-001 с семью исходами, индикатор «Обработка запроса», повтор после ошибки, проверка пустого вопроса, временные чаты в памяти вкладки, режим передаётся с вопросом, инструкция для проверяющего в чате «Как проверить демо».
