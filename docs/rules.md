# Системные правила и инварианты

«Обязательно» ниже означает силу правила после его согласования для реализации. Правило DRAFT/PROPOSED не становится APPROVED из-за нормативной формулировки. Открытые зависимости перечислены в [реестре решений](decisions/README.md).

| ID | Правило | Сила | Статус | Источник |
|---|---|---|---|---|
| RULE-SCOPE-001 | Разработка следует спецификации; сейчас создавать только документацию. Для кода нужны отдельное указание и APPROVED выбранного объёма | Обязательное сейчас | CONFIRMED | SRC-001/SRC-002 |
| RULE-CHAT-001 | Каждый вопрос самостоятельный; история UI не передаётся в retrieval/LLM | Обязательное направление | CONFIRMED | SRC-002 |
| RULE-INPUT-001 | Принимать строку после удаления крайних пробелов, не пустую и не длиннее MAX_QUESTION_CHARS; считать Unicode-кодовые точки. Внутренние пробелы сохранять | Обязательное после согласования | DRAFT | SRC-003 |
| RULE-RAG-001 | Retrieval использует BM25; версии корпуса и обработки фиксируются | Обязательное направление | CONFIRMED | SRC-001/SRC-002 |
| RULE-RAG-002 | Один запрос использует один неизменяемый снимок индекса; score не является вероятностью правильности ответа | Обязательное после согласования | DRAFT | SRC-003/SRC-004 |
| RULE-RAG-003 | При отсутствии кандидатов по политике отбора LLM не вызывается; возвращается insufficient/no_candidates | Обязательное после согласования | DRAFT | SRC-003 |
| RULE-GEN-001 | Ответ должен опираться на переданный контекст. Неполноту и обнаруженные противоречия обозначать; не утверждать неподтверждённые корпоративные сведения | Обязательное направление | CONFIRMED | SRC-002 |
| RULE-GEN-002 | Инструкции внутри документов и вопроса не могут изменять системные правила; документы — недоверенные данные | Обязательное после согласования | PROPOSED | SRC-003 |
| RULE-SOURCE-001 | Ссылка ответа указывает только на фрагмент переданного контекста и его версию; нельзя заменять его текущим документом молча | Обязательное после согласования | DRAFT | SRC-003 |
| RULE-ERROR-001 | Отказ поиска/модели не представлять как отсутствие знаний; пользователю не раскрывать секреты, пути файлов и stack trace | Обязательное после согласования | DRAFT | SRC-003 |
| RULE-REQUEST-001 | В текущем чате один активный запрос; автоматических повторов нет. request_id — корреляция, не гарантия идемпотентности | Обязательное после согласования | DRAFT | SRC-003 |
| RULE-SEC-001 | Секреты задаются серверной конфигурацией вне Git; в клиентские ответы, логи и примеры не включаются | Обязательное направление | CONFIRMED | SRC-001 |
| RULE-SEC-002 | До передачи реальных документов модели определить допустимость, среду доступа и хранение данных. До этого использовать только разрешённые/синтетические материалы | Обязательное после согласования | PROPOSED | SRC-003; OPEN-003/005 |
| RULE-LOG-001 | Технические логи по умолчанию содержат ID, этап, длительность и код ошибки; не содержат вопрос, полный prompt или документы | Обязательное после согласования | PROPOSED | SRC-003 |
| RULE-EVAL-001 | Отделять технические проверки от семантической оценки и продуктового эксперимента; не подменять конверсию качеством ответов | Обязательное направление | CONFIRMED | SRC-001/SRC-002 |
| RULE-DOMAIN-001 | Дата файла сама по себе не определяет достоверность; политика актуальности/приоритета требует эксперта | Обязательное после согласования | PROPOSED | SRC-003; OPEN-004 |
| RULE-UI-001 | Отображать ответ и документы как безопасный текст; HTML/скрипты и произвольные внешние ссылки источниками не выполнять | Обязательное после согласования | PROPOSED | SRC-003 |

## Рекомендации

PROPOSED, SRC-003: предпочитать компактные ответы; фиксировать небольшое число сравниваемых конфигураций; сначала измерять базовый поиск; не добавлять механизм только ради привычной архитектуры. Рекомендации не являются критериями приёмки.

## Проверки правил

RULE-INPUT-001 — BEH-CHAT-002/003 и TEST-API-001; RULE-RAG-001/002 — TEST-RAG-002; RULE-RAG-003 — TEST-CHAT-004; RULE-GEN-001 — экспертная оценка плюс тесты с управляемым генератором; RULE-GEN-002 — TEST-RAG-003; RULE-SOURCE-001 — TEST-CHAT-010/015; RULE-ERROR-001/REQUEST-001 — ошибочные сценарии; RULE-SEC-001/LOG-001/UI-001 — TEST-SEC-001; RULE-EVAL-001 — TEST-EVAL-001 и исследовательский протокол.

Наличие prompt-инструкции или проверки ID не доказывает соблюдение смыслового правила во всех ответах. Остаточные ошибки отражаются в результатах оценки.
