# Словарь

Пояснения терминов, кодов и статусов, которые встречаются в документации. Словарь объясняет слова, но не задаёт требований. Точные определения — в документах, на которые он ссылается. Обзор проекта — в [overview.md](overview.md).

## Термины

| Термин | Что значит |
|---|---|
| НИРС | Научно-исследовательская работа студентов — рамка, в которой делается проект |
| MVP | Первая минимальная версия продукта, достаточная для проверки идеи |
| Онбординг | Ввод нового сотрудника в работу |
| Конверсия | Доля обращений клиентов, закончившихся сделкой |
| RAG | Retrieval-Augmented Generation: ответ языковой модели по найденным в документах фрагментам, а не «по памяти» модели |
| LLM, языковая модель | Нейросеть, которая составляет текст ответа (например, модели семейств GPT или Claude); конкретная модель для проекта не выбрана |
| Провайдер | Сервис, через который вызывается языковая модель |
| Prompt | Текст-задание для языковой модели: инструкции, вопрос и найденные фрагменты |
| Prompt injection | Попытка подменить инструкции модели через текст вопроса или документа |
| Режим | «Спросить» или «Продавать»: определяет, в какой базе знаний искать ответ ([решение](decisions/README.md#adr-004--две-базы-знаний-по-режимам-спросить-и-продавать)) |
| База знаний | Набор документов одного режима вместе с поисковым индексом |
| Корпус | Набор документов, из которых собирается база знаний |
| Фрагмент (chunk) | Небольшой кусок текста документа; поиск и ссылки работают с фрагментами, а не с целыми документами |
| Индекс | Структура для быстрого поиска по фрагментам |
| Снимок (snapshot) | Готовая неизменяемая версия базы: фрагменты, индекс и описание. Один вопрос всегда обрабатывается по одному снимку |
| Версия индекса (index_version) | Уникальный код снимка; по нему можно точно воспроизвести, по каким данным дан ответ |
| Manifest | Файл-опись снимка: какие документы и фрагменты в нём, с какими настройками собран |
| Подготовка базы (ingestion, индексирование) | Отдельная операция: из документов получить фрагменты, построить индекс и опубликовать снимок. Выполняется заранее, не через сайт |
| BM25 | Классический алгоритм поиска по совпадению слов: чем больше редких слов вопроса во фрагменте, тем выше фрагмент. Смысл не «понимает» |
| Retrieval, поиск | Шаг, на котором по вопросу находятся подходящие фрагменты |
| Кандидаты | Фрагменты, найденные поиском, — до отбора |
| Контекст | Фрагменты, отобранные для передачи модели; ограничены размером запроса к модели |
| Генерация | Шаг, на котором модель составляет ответ по контексту |
| Источник, ссылка S1, S2… | Указание в ответе на фрагмент, из которого взято утверждение |
| Excerpt | Короткая выдержка из фрагмента-источника, показываемая рядом с ответом |
| Исход (outcome) | Тип результата: ответ, частичный ответ, недостаточно сведений, нужно уточнение, противоречие ([таблица](overview.md#какие-ответы-может-дать-система)) |
| API | Правила обмена данными между страницей и сервером |
| Envelope | Общая «обёртка» ответа сервера: служебные поля вокруг основного содержимого |
| request_id | Код конкретного запроса для поиска его в технических журналах |
| Таймаут | Предельное время ожидания, после которого операция считается неудавшейся |
| Frontend | Страница в браузере: интерфейс пользователя |
| Backend | Серверная часть: проверка вопроса, поиск, вызов модели, проверка ответа |
| Заглушка (mock) | Временная имитация части системы. В демо `Web/` заглушка изображает сервер |
| Recall@k, Precision@k, Hit@k | Показатели качества поиска: сколько нужных фрагментов нашлось среди первых k, сколько из первых k действительно нужны, нашёлся ли хотя бы один ([подробно](rag/evaluation.md)) |
| Разметка | Указание экспертом, какие фрагменты правильно отвечают на вопрос; нужна для оценки поиска |
| Development- и test-набор | Вопросы для настройки системы и отдельные вопросы для итоговой проверки, которые при настройке не используются |
| Эксперт предметной области | Специалист по продажам недвижимости, который проверяет требования и качество ответов |
| Domain Expert Review | Порядок разбора новых материалов от эксперта или коллег ([описание](../Service/README.md)) |
| Трассируемость | Возможность пройти по цепочке «цель → требование → сценарий → интерфейс/API → код → тест» ([карта](project-map.md)) |

## Коды в документах

Каждое важное утверждение имеет постоянный код. Код не меняется, даже если утверждение отменено.

| Префикс | Что обозначает | Где описаны |
|---|---|---|
| GOAL | Цель проекта | [product-context.md](product-context.md) |
| REQ | Требование к системе | [product-context.md](product-context.md) |
| RULE | Правило, которое нельзя нарушать | [rules.md](rules.md) |
| BEH | Сценарий поведения: «дано — когда — тогда» | [behavior.md](behavior.md) |
| TEST | Запланированная проверка (тесты ещё не написаны) | [behavior.md](behavior.md) |
| UI | Элемент интерфейса | [interface.md](interface.md) |
| API | Контракт обмена данными | [backend/api.md](backend/api.md) |
| ARCH | Компонент системы | [backend/architecture.md](backend/architecture.md), [rag/architecture.md](rag/architecture.md) |
| ADR | Принятое архитектурное решение с причинами | [decisions/README.md](decisions/README.md) |
| OPEN | Вопрос, на который пока нет ответа | [decisions/README.md](decisions/README.md) |
| HYP | Исследовательская гипотеза | [research/hypotheses.md](research/hypotheses.md) |
| SRC | Источник: откуда взято утверждение | [README.md](README.md#источники) |
| M | Пункт сравнения с макетом | [interface.md](interface.md#сверка-с-макетом-src-005) |

Запись «BEH-CHAT-001…015» означает все сценарии с 001 по 015 включительно.

## Статусы

| Статус | Простыми словами |
|---|---|
| PROPOSED | Предложение ИИ-агента, никем не подтверждено |
| DRAFT | Подробный черновик, ждёт проверки |
| NEEDS_DOMAIN_REVIEW | Предположение о предметной области; должен проверить эксперт |
| CONFIRMED | Человек явно подтвердил содержание. Это ещё не разрешение писать код |
| APPROVED | Разрешено реализовать конкретный объём. Сейчас нет ни у одного пункта |
| DEPRECATED | Отменено; код сохраняется, чтобы не потерять историю |

Нормативные слова вроде «должен» в черновиках не делают их согласованными: статус важнее формулировки.
