# Работа со спецификациями

Дополняет [корневую инструкцию](../AGENTS.md). Не дублирует продуктовые правила.

1. Читать основной источник изменяемого содержания: требования — `product-context.md`, поведение — `behavior.md`, инварианты — `rules.md`, API — `backend/api.md`, алгоритмы — профильный файл `rag/`. В других документах оставлять краткое объяснение и ссылку.
2. Новый ID выдавать после поиска всех упоминаний; существующие не переименовывать ради оформления. Для удалённого требования сохранять DEPRECATED и причину.
3. Помечать новые детали DRAFT/PROPOSED и SRC-003; предметные допущения — NEEDS_DOMAIN_REVIEW с владельцем проверки. Не повышать статус вследствие отсутствия возражений или истечения времени.
4. Общее SRC-002 подтверждает ранее представленную концепцию, но не новые поля API, алгоритмы и параметры этого комплекта. Их согласование должно быть отдельным и адресным.
5. Указывать открытые параметры по именам и единицам, не заменять их случайными числами. Без согласованных значений не объявлять этап готовым к реализации или результат успешным.
6. Новые материалы обрабатывать по [Domain Expert Review](../Service/README.md). До значимого изменения показать предложение замены и влияние на ID; сохранять источник и историю согласования.
7. При изменении поведения синхронно обновлять интерфейс, контракт, правила, план тестов и трассируемость. При изменении корпуса пересматривать оценочную разметку и версии экспериментов.
8. Перед завершением проверять относительные Markdown-ссылки и якоря, уникальность определений ID, разрешимость упоминаний, покрытие сценариев, согласованность статусов, исходов API и ошибок. Техническая и семантическая проверки не взаимозаменяемы.
9. Различать «документ описывает», «тест запланирован», «код реализован», «тест выполнен». В истории отражать только факты. Не переносить незавершённые предложения в историю как принятые решения.

Этот комплект создан без приложения и автоматизированных тестов. Независимые исправления документации разрешены пользователем; реализация и существенная смена согласованного направления требуют его отдельного указания.
