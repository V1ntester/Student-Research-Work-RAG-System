# Рабочий контекст изменений

Папка хранит незавершённые задачи спецификации/разработки и состояние работы. Это не второй источник истины требований и не история принятых решений. Долгосрочные спецификации находятся в docs, подтверждения — в источниках и change-history.

Перед задачей проверить рабочее дерево и применимые записи `active/`. Не считать запись устаревшей только по возрасту; сверить с файлами/Git. Сейчас [базовая запись](active/specification-baseline.md) описывает создание документации и открытые вопросы.

## Минимальная запись

Дата; задача и источники; что изменено; затронутые ID/файлы; проверки с фактическим результатом; незавершённое; следующий шаг. Отдельно:

- **Рабочее дерево:** ещё не зафиксированные изменения; проверять Git status/diff.
- **Локальные коммиты:** конкретные hash только если действительно созданы.
- **Remote:** факт отправки/проверенный remote commit; локальный коммит не означает push. Если не проверено, так и написать.

Не копировать полный diff и все требования. После интеграции обновить статус записи и перенести согласованное значимое изменение в docs/change-history.md. Удалять рабочую запись только после сохранения нужного контекста. Секреты и закрытые исходники сюда не включать.
